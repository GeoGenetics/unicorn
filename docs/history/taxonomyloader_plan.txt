**Design**

This document describes the methodology to follow for taxonomy loader optimization.

Problem - The taxonomy loader owns persistent strings through individual
          `strdup()` allocations. Closing a production taxonomy therefore
          performs one `free()` per retained scientific name and accession.
          The current production fixture retains 2,668,535 scientific names
          and 1,329,902 accession keys: about four million individual frees.

Scope:

- Optimize only persistent string ownership for taxonomy names and plain-text
  accession keys.
- Preserve public taxonomy APIs, hash types, lookup behavior, and the 64-shard
  accession map layout.
- Keep serialized `.khash` loading behavior unchanged.
- Do not combine this change with the separate `_loaddqueue()` capacity
  over-allocation fix.

Non-goals:

- Do not change accession parsing, duplicate reporting, taxonomy semantics,
  or rank/name selection.
- Do not introduce a production dependency on the unapproved `.khash` path.

Proposed solution:

Add one small internal `strarena_t` utility:

- linked allocation blocks with `capacity` and `used`
- `strarena_strdup()` copies a string into the current block
- allocates a new block only when necessary
- `strarena_destroy()` frees its blocks once

The hash maps still store ordinary `const char *` pointers. Only allocation
ownership changes.

Arena invariants:

- A returned string pointer is never moved for the lifetime of its map.
- Blocks are linked, never grown with `realloc()`.
- Arena allocation happens only in sequential loader stages; worker threads
  only read the already-created key pointers while inserting into shards.
- A failed allocation is reported to the caller and leaves no partially
  initialized ownership state behind.
- A string larger than the default block size receives a suitably sized
  dedicated block.

Ownership would become:

| Data | Current ownership | Arena ownership |
|---|---|---|
| Scientific names | one `strdup()` per name | `utax_t.name_arena` |
| Plain-text accession keys | one `strdup()` per accession | `emap_chr2int_t.key_arena` |
| Serialized `.khash` keys | contiguous file-loaded buffers | unchanged |

This keeps the unapproved serialized path completely out of the production solution.

**Acceptance Criteria**

- Plain-text accession and scientific-name lookups return the same values as
  before the change.
- Conflicting duplicate accessions retain the first mapping and preserve the
  reported duplicate count.
- The serialized `.khash` path still loads and closes without touching arena
  ownership.
- No per-entry `free()` loop remains for arena-owned names or raw accession
  keys.
- Repeated load/close validation is clean under an allocation checker.
- The production benchmark demonstrates a substantial taxonomy-close speedup
  without a correctness or unacceptable memory regression.

**One deliberate tradeoff**

Duplicate accession lines will consume arena space until close, whereas today their temporary strings are freed immediately. That is acceptable if duplicates are rare, which the loader already appears to assume. We should record duplicate count and arena bytes during the benchmark; if duplicates are unexpectedly common, we can add a second-pass duplicate optimization later without compromising the core design.

The queue over-reservation in `_loaddqueue()` is a separate loader-memory issue. I would keep it out of the first arena change, then address it in a small follow-up once teardown is fast and benchmarked.
