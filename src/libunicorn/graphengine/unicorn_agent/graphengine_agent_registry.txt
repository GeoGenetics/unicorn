Unicorn Graph Engine Agent Registry
===================================

Status and Authority
--------------------

This document describes the live backend-owned read-only V1 registry.

Runtime authority:

- `unicorn_agent/registry.py`
- `unicorn_agent/tools.py`

Provider input contract:

- `rewrite/contracts/provider_adapter_input.schema.json`

The browser does not define, validate, dispatch, or execute Agent tools.


Registry Invariants
-------------------

Every tool definition contains:

- stable dotted lowercase `tool_id`
- description
- when-to-use guidance
- output summary
- JSON argument schema
- backend handler
- mutation flag

Only tools with `mutation: false` are advertised. Before dispatch, the registry
rejects:

- unknown IDs with `unknown_tool`
- invalid arguments with `invalid_tool_arguments`
- mutation tools with `mutation_not_allowed`

Unexpected handler failures become `tool_execution_failed`. Tool service
errors can be returned as structured failed tool results and reinjected into
the provider loop.


Read-Only Tool Surface
----------------------

`graph.context`

- Purpose: return the compact backend-authoritative context already associated
  with the turn.
- Use for selected dataset count, visible-node count, selected-node count,
  root/focus summary, `min_reads`, and count mode.
- Arguments: `{}`.
- Output: `session`, `datasets`, `tree`, `filters`, `metadata`, and
  `report_state`.

`datasets.selected`

- Purpose: inspect the active backend datasets.
- Arguments: `{}`.
- Output:
  - dataset count
  - aggregate total reads
  - direct taxa count
  - filename, total reads, and total taxa for each active dataset

`metadata.summary`

- Purpose: discover whether metadata is loaded and which fields are available.
- Arguments: `{}`.
- Output:
  - load state and metadata filename
  - field names and field count
  - total, matched, and unmatched row counts
  - selected-dataset metadata coverage
- It does not return raw metadata rows or complete per-dataset dictionaries.

`metadata.compare_selected`

- Purpose: compare counts for selected nodes across values of one metadata
  field.
- Arguments:
  - required non-empty string `field`
  - optional unique `taxids`, restricted to the current selection, maximum 50
  - optional `limit`, from 1 through 50
- Output:
  - active direct/subtree count mode
  - metadata groups and dataset membership
  - node-centric group counts
  - bounded pairwise group summaries
  - truncation indicators
  - explicit interpretation caveat
- Results are descriptive raw counts. They are not normalized, causal, or
  statistical tests.

`nodes.selected`

- Purpose: resolve the current browser-requested node selection against the
  backend-visible tree.
- Arguments: `{}`.
- Output: selected taxids with names, ranks, direct/subtree counts, and visible
  child counts.

`nodes.find_visible`

- Purpose: ground a node name or unverified taxid before detail lookup.
- Arguments:
  - required non-empty string `query`
  - optional `limit`, from 1 through 100
- Output: ordered threshold-visible matches with taxid, counts, match type, and
  match score.
- Matching supports taxid, exact name, prefix, substring, and scored close-name
  matches for minor spelling errors.

`node.details`

- Purpose: return authoritative detail for one or more grounded taxids.
- Arguments:
  - integer `taxid`, or
  - unique integer `taxids`, maximum 100
- Output: node identity, lineage, direct/subtree counts, visible child count,
  and per-dataset counts.

`table.view`

- Purpose: return ranked rows for the visible root or one visible-node scope.
- Arguments:
  - optional `scope`: `root` or `node`
  - required integer `taxid` when `scope` is `node`
  - optional `sort`: `direct` or `subtree`
  - optional `limit`, from 1 through 1000
- Output: target summary and ordered count rows.


Expected Multi-Tool Workflows
-----------------------------

Named-node details:

```text
nodes.find_visible -> node.details -> final answer
```

Selected-node details:

```text
nodes.selected -> node.details with all grounded taxids -> final answer
```

Metadata field discovery:

```text
metadata.summary -> final answer
```

Metadata comparison for selected nodes:

```text
metadata.summary when field discovery is needed
metadata.compare_selected -> final answer
```

Metadata comparison for one named selected node:

```text
nodes.find_visible
metadata.compare_selected with the grounded selected taxid
final answer
```

The provider must not repeat a completed call with identical arguments.


Backend Ownership
-----------------

Each turn creates a request-scoped `ReadOnlyToolService`. The service:

- validates the browser turn request
- rebuilds the requested graph scope through the backend store
- verifies datasets and taxonomy
- applies `min_reads`
- verifies selected and focused taxids against the visible tree
- executes only backend handlers
- never calls browser callbacks
- never mutates graph state

Provider adapters receive tool definitions and normalized tool results. They
never dispatch tools themselves.
