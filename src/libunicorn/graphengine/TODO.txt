Unicorn Graph Engine TODO

Current status
- Graphengine now has one intended operating model: backend-required mode.
- If a user is working on one machine, they should run the backend locally and
  connect the UI to `localhost`.
- Remote tree rendering is server-authoritative.
- Backend owns dataset loading, taxonomy loading, visible tree slicing, tooltip data, table data, and subtree reports.
- Client renders tree, requests visible slices from the backend, and now supports:
  - delayed tooltips
  - drag-to-pan
  - root/expand interaction
  - server-backed tooltip
  - server-backed top table
  - subtree report
  - subtree matrix export
  - linear/log minimum subtree read slider
- Agent panel exists in the UI and already supports:
  - client-side transcript/history
  - provider/model configuration controls
  - constrained Unicorn-native tools
  - client-side provider turn loop
  - mock provider runtime for agentic prototyping

API and semantics
- Keep the backend as the source of truth for all graphengine operation.
- Do not preserve a separate local dataset/tree/report execution path.
- Preserve the current visible-tree semantics:
  - root is always returned
  - visible nodes are those that survive filters and lie on the expanded frontier
  - `child_count` is filtered child count, not raw taxonomy child count
  - collapsed nodes still carry subtree totals
- Keep dataset/taxonomy changes invalidating expanded state.
- Keep `min_reads` preserving the expansion request while allowing the backend to prune branches.

Near-term next steps
1. Finish the backend-only cleanup.
Current state:
- the codebase still contains local-vs-remote branching
- the intended product direction is now one backend-required path
Why:
- this removes the biggest source of semantic drift before more agent work

2. Finish the first real provider-backed agent path.
Current state:
- the UI contract and client-side turn loop are already implemented
- the remaining gap is replacing mock runtime with one real provider adapter
Why:
- this is the most important next milestone for the new agentic flow

3. Selected-node matrix views by rank.
Current direction:
- from one or more selected nodes, build a count matrix of directly assigned reads collapsed by rank
- keep this as a report type alongside subtree report
Why:
- this is especially relevant for the wheat simulation because it can show where optimal-alignment filtering pushes reads deeper in the taxonomy

Caching and performance
Do not implement yet unless a real bottleneck is identified by measurement.
When ready, cache:
- visible tree by selected files + taxonomy files + expanded set + `min_reads`
- tooltip by taxid + same context
- table by scope + taxid + same context
- subtree report by taxid + same context

Potential performance upgrades after measurement
- prefetch likely next expansions
- prefetch tooltip payloads for visible nodes near the cursor path
- prefetch subtree report for the currently selected node
- delta transport for visible tree updates
- avoid fetching `/tree-model` for remote `Uncollapse Tips`
