I would structure this as a backend-first replacement project with a clean deletion boundary. We preserve only test evidence and agreed data contracts, then remove the old runtime rather than operating two agent frameworks in parallel.

## Phase 0: Freeze Scope

Decide what the first rewritten version must support.

Keep:

- backend-authoritative graph state
- read-only agent behavior
- OpenAI
- Google Gemini
- local OpenAI-compatible/vLLM
- JSON-only provider responses
- Unicorn-controlled tool loop
- raw provider-response logging
- existing Agent panel configuration fields

Defer:

- graph mutations
- native provider tool calling
- streaming responses
- persistent multi-user backend sessions
- advanced tool discovery
- token compaction beyond obvious duplication removal

Definition of done:

- one short scope document clearly distinguishes V1 from deferred work.

## Phase 7: Implement Tracing First

STATE - COMPLETE

Before real provider calls, implement the full event stream with a fake provider.

Suggested storage:

```text
logs/agent_trace/YYYY-MM-DD/<turn_id>.jsonl
```

Use a path based on `server_app.py` or an explicit environment variable, not the server’s current working directory.

Minimum events:

```text
turn_received
turn_validated
context_built
iteration_started
provider_request_mapped
provider_http_started
provider_http_completed
provider_output_extracted
provider_response_normalized
tool_call_validated
tool_execution_started
tool_execution_completed
iteration_completed
turn_completed
turn_failed
```

Trace requirements:

- ordered `sequence`;
- elapsed time;
- payload byte size;
- HTTP status;
- raw provider response;
- sanitized parsing input;
- normalized response;
- exact tool arguments and results;
- redacted credentials.

Implemented:

- promoted the complete Phase 7 lifecycle into the authoritative V1 trace
  schema
- added ordered events for validation, context, every provider iteration,
  provider transport, output extraction, normalization, tool validation and
  execution, result reinjection, and terminal turn state
- added deterministic UTF-8 JSON payload-size measurements
- added provider transport envelopes carrying HTTP status and native response
  bodies
- added provider output inspection carrying both raw model text and the exact
  sanitized parser input
- retained exact tool arguments and complete validated tool results
- added `JsonlTraceStore` with immediate append-only persistence
- default trace storage to
  `logs/agent_trace/YYYY-MM-DD/<turn_id>.jsonl` relative to graphengine
- allow an explicit trace root through
  `UNICORN_GRAPHENGINE_AGENT_TRACE_DIR`
- recursively remove credential-bearing keys and redact transient secret
  values before validation or persistence
- discard transient redaction secrets after the terminal event
- keep the in-memory trace sink available for deterministic unit tests
- switch the server runtime to persistent JSONL tracing while retaining the
  deferred no-network provider boundary
- add fixture-driven coverage for complete multi-iteration JSONL traces

## Phase 9: Implement the Orchestrator with a Fake Provider

STATE - COMPLETE

The orchestrator should:

1. validate the request;
2. build context;
3. start iteration zero;
4. invoke the provider adapter;
5. normalize the response;
6. validate and execute tool calls;
7. reinject tool results;
8. stop on final answer, error, repetition, or iteration limit;
9. return the final result with `trace_id`.

Use a deterministic fake provider first so the entire loop is testable without external services.

Implemented:

- retained the backend-owned state machine as the only turn-loop owner
- validate the browser request and rebuild compact backend-authoritative
  context before iteration zero
- map, execute, inspect, parse, and validate every provider response through
  the frozen adapter boundary
- validate and dispatch read-only tool calls through the backend registry
- reinject complete validated tool results into the next provider iteration
- stop deterministically on assistant/final answers, provider errors, invalid
  tools or arguments, repeated calls, and the configured iteration limit
- return one validated browser result containing the persistent `trace_id`
- add a package-owned deterministic fake adapter that requests
  `graph.context` on iteration zero and consumes its result on iteration one
- switch the temporary backend runtime from a deferred terminal error to the
  deterministic two-iteration fake flow
- add runtime-level coverage proving tool execution, result reinjection,
  successful completion, and a complete persistent JSONL trace without
  contacting an external provider

## Phase 10: Add Provider Adapters

STATE - COMPLETE

Recommended order:

1. local OpenAI-compatible/vLLM
2. Google
3. OpenAI

Each adapter must expose only:

```text
map_request(canonical_input) -> provider-native request
send_request(provider-native request) -> transport response
inspect_response(raw provider response) -> raw and sanitized output
parse_response(sanitized output) -> normalized response
```

Provider-specific compatibility handling remains inside its adapter.

The orchestrator must never know about:

- OpenAI Responses objects;
- Gemini Interactions objects;
- `choices[*].message.content`;
- `<think>` blocks;
- fenced JSON extraction.

Implemented:

- added one request-scoped adapter factory keyed by the validated provider name
- implemented local OpenAI-compatible/vLLM chat-completion transport first
- retained local reasoning compatibility entirely inside that adapter:
  - raw `<think>...</think>` content remains available to tracing
  - think blocks are removed only from parser input
  - the last fenced JSON block or first recoverable JSON object is extracted
  - historical `tool`/`input` and legacy tool-name forms are normalized
- implemented Google Gemini Interactions transport with JSON structured output,
  `x-goog-api-key` authentication, and current `steps` response extraction
- implemented OpenAI Responses transport with strict JSON structured output,
  bearer authentication, output-message extraction, and refusal handling
- construct provider endpoints from optional validated base URLs
- keep API keys ephemeral in request headers and outside mapped requests,
  provider input, normalized responses, and traces
- preserve provider HTTP status and complete native JSON response envelopes for
  the ordered trace
- remove obvious prompt duplication by serializing conversation and current
  turn state exactly once in the provider-native request
- keep endpoint mapping, HTTP transport, native response extraction, output
  sanitization, and compatibility normalization out of the orchestrator
- switch the backend runtime from the Phase 9 fake adapter to request-scoped
  live adapter selection
- retain the deterministic fake adapter only as an injected unit-test boundary
- update fixture tests to exercise the four-method adapter interface
- add network-free transport coverage for adapter selection, endpoint mapping,
  authentication headers, request bodies, API errors, and unsafe base URLs
