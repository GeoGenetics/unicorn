Unicorn Agent Rewrite - Phase 0 Scope Freeze
=============================================

Status
------

This document freezes the scope of the first rewritten agent framework.

The V1 rewrite is a backend-first replacement of the current agent runtime. Its
goal is a small, read-only, provider-neutral agent loop whose complete execution
can be traced from the browser prompt through the model provider and back.


Required V1 Scope
-----------------

V1 must preserve:

- backend-authoritative graph state
- read-only agent behavior
- OpenAI provider support
- Google Gemini provider support
- local OpenAI-compatible/vLLM provider support
- JSON-only provider responses
- a Unicorn-controlled tool loop
- raw provider-response logging
- the existing Agent panel configuration fields:
  - provider
  - model
  - API key
  - optional base URL
  - prompt


V1 Ownership Rules
------------------

- The browser owns Agent panel interaction and transcript rendering.
- The browser sends the prompt, provider configuration, and explicit transient
  UI state needed to interpret the active graph.
- The backend owns context construction, provider mapping and transport,
  response normalization, tool validation and execution, loop orchestration,
  and persistent tracing.
- Unicorn, not the provider, decides whether a requested tool is allowed and
  executes every tool call.
- Provider-specific behavior must remain inside provider adapters.
- Raw provider output must remain available in traces even when a sanitized
  copy is used for JSON parsing.
- Credentials are transport-only data and must never be written to traces.


Deferred Work
-------------

The following are outside V1:

- graph mutations or other state-changing tools
- native provider tool calling
- streaming provider or transcript responses
- persistent multi-user backend sessions
- advanced tool discovery such as dynamic tool catalogs or `get_tool_info`
- token compaction beyond removing obvious duplication

Deferred features must not add compatibility layers, hidden branches, or
parallel execution paths to the V1 implementation.


V1 Completion Boundary
----------------------

V1 is in scope-complete when:

- all three provider targets use the same Unicorn-internal turn contract
- the backend executes the complete read-only provider/tool loop
- the browser makes one agent-turn request and renders one normalized result
- every turn can be reconstructed from one ordered trace using a stable turn ID
- raw provider responses are retained with secrets redacted
- no state-mutating tool can be advertised or executed

Features listed under Deferred Work are not required for V1 completion.
