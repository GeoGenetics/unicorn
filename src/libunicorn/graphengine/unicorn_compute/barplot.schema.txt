Unicorn Compute Barplot Schema
==============================

Purpose
-------

This document defines the first compute-side input/output contract for
count-matrix barplots.

The goal is to let `unicorn_compute` transform backend-authoritative Unicorn
analysis data into a plot-ready payload, while leaving popup lifecycle and
Plotly rendering in the frontend runtime.


Input contract
--------------

The barplot compute routine accepts:

```json
{
  "report": {
    "summary": {
      "selected_taxids": [4565, 4571],
      "selected_node_count": 2,
      "dataset_names": [
        "Lib_sim1_collapsed.alnfilt.bdamage.txt",
        "Lib_sim1_collapsed.bdamage.txt"
      ],
      "total_direct": 1234,
      "total_subtree": 5678
    },
    "matrix": {
      "rows": [
        {
          "taxid": 4565,
          "name": "Triticum",
          "rank": "genus",
          "direct": 120,
          "subtree": 600,
          "datasets": [
            {
              "dataset": "Lib_sim1_collapsed.alnfilt.bdamage.txt",
              "direct": 100,
              "subtree": 500
            },
            {
              "dataset": "Lib_sim1_collapsed.bdamage.txt",
              "direct": 20,
              "subtree": 100
            }
          ]
        }
      ],
      "dataset_names": [
        "Lib_sim1_collapsed.alnfilt.bdamage.txt",
        "Lib_sim1_collapsed.bdamage.txt"
      ],
      "row_count": 1
    }
  },
  "count_mode": "direct",
  "dataset_display": {
    "Lib_sim1_collapsed.alnfilt.bdamage.txt": {
      "filename": "Lib_sim1_collapsed.alnfilt.bdamage.txt",
      "metadata_field": "group",
      "metadata_value": "treated",
      "color": "#c85f43",
      "label": "Lib_sim1_collapsed.alnfilt.bdamage.txt [group: treated]",
      "missing": false
    },
    "Lib_sim1_collapsed.bdamage.txt": {
      "filename": "Lib_sim1_collapsed.bdamage.txt",
      "metadata_field": "group",
      "metadata_value": "control",
      "color": "#255f75",
      "label": "Lib_sim1_collapsed.bdamage.txt [group: control]",
      "missing": false
    }
  }
}
```

Rules:

- `report` must be a backend-authoritative selected-node count matrix payload
- `count_mode` must be either:
  - `direct`
  - `subtree`
- `dataset_display` is optional
- `dataset_display` should come from Unicorn's shared metadata resolver
- if `dataset_display` is omitted, the compute layer falls back to raw dataset names
- legacy `dataset_colors` may still be accepted as a fallback input, but the preferred V1.1 path is the resolver-driven `dataset_display`


Output contract
---------------

The compute routine returns:

```json
{
  "compute_version": "v1",
  "plot_type": "barplot",
  "count_mode": "direct",
  "title": "Selected-node direct counts",
  "x": [
    "Triticum (4565)",
    "Aegilops (4480)"
  ],
  "traces": [
    {
      "name": "Lib_sim1_collapsed.alnfilt.bdamage.txt [group: treated]",
      "dataset": "Lib_sim1_collapsed.alnfilt.bdamage.txt",
      "metadata_field": "group",
      "metadata_value": "treated",
      "missing": false,
      "color": "#c85f43",
      "y": [100, 23]
    },
    {
      "name": "Lib_sim1_collapsed.bdamage.txt [group: control]",
      "dataset": "Lib_sim1_collapsed.bdamage.txt",
      "metadata_field": "group",
      "metadata_value": "control",
      "missing": false,
      "color": "#255f75",
      "y": [20, 5]
    }
  ],
  "summary": {
    "selected_node_count": 2,
    "dataset_count": 2
  }
}
```

Rules:

- `compute_version` identifies the compute schema version
- `plot_type` is always `barplot`
- `count_mode` echoes the selected mode
- `x` contains normalized selected-node labels
- each trace corresponds to one dataset
- `trace.name` should prefer the resolver-provided display label when available
- `trace.dataset` keeps the canonical dataset filename
- `trace.metadata_field`, `trace.metadata_value`, and `trace.missing` mirror the shared resolver payload when available
- `trace.y` length must match `x` length
- `summary` is intentionally compact


Non-goals
---------

- no Plotly-specific popup or window handling here
- no raw frontend DOM concerns here
- no mixed direct+subtree barplot mode in V1


V1 policy
---------

- V1 supports only `direct` and `subtree`
- `both` remains a frontend display mode, not a compute barplot mode
